聚簇索引和非聚簇索引

Clustered index，聚簇索引即索引结构和数据一起存放的索引。

对于InnoDB，表的.ibd文件就包含了该表的索引和数据，B+树的非叶子节点存储索引，叶子节点存储数据和索引（一般对我们开发来说就是主键索引）



## 索引优化练习

### 案例一

```sql
-- 用户表（user_code 关联字段暂时没有索引）
CREATE TABLE users (
    user_id INT PRIMARY KEY AUTO_INCREMENT,
    user_code VARCHAR(20),
    user_name VARCHAR(50),
    city VARCHAR(20)
) ENGINE=InnoDB;

-- 日志表（action + log_time 有复合索引，但 user_code 无单独索引）
CREATE TABLE user_logs (
    log_id INT PRIMARY KEY AUTO_INCREMENT,
    user_code VARCHAR(20),
    action VARCHAR(20),
    log_time DATETIME,
    INDEX idx_action_time (action, log_time)  -- 为了过滤条件
) ENGINE=InnoDB;


SET SESSION cte_max_recursion_depth = 1000000;
-- 50万用户
INSERT INTO users (user_code, user_name, city)
WITH RECURSIVE seq(n) AS (
    SELECT 0 UNION ALL SELECT n+1 FROM seq WHERE n < 499999
)
SELECT
    CONCAT('U', LPAD(n, 6, '0')),
    CONCAT('User_', n),
    ELT(1 + FLOOR(RAND()*5), '北京','上海','广州','深圳','杭州')
FROM seq;

-- 200万日志（0~999 序列两次交叉连接 = 1,000,000，再 ×2 简单办法）
INSERT INTO user_logs (user_code, action, log_time)
WITH RECURSIVE seq(n) AS (
    SELECT 0 UNION ALL SELECT n+1 FROM seq WHERE n < 999
)
SELECT
    CONCAT('U', LPAD(FLOOR(1 + RAND() * 500000), 6, '0')),
    ELT(1 + FLOOR(RAND()*4), 'login','logout','click','purchase'),
    DATE_ADD('2024-01-01', INTERVAL FLOOR(RAND() * 500) DAY)
FROM seq AS a CROSS JOIN seq AS b;   -- 100万行
-- 再重复插入一次让数据达到200万（实际可用临时表多次插入，这里仅示意）
INSERT INTO user_logs (user_code, action, log_time) SELECT user_code, action, log_time FROM user_logs;

SELECT u.user_name, l.action, l.log_time
FROM user_logs l
JOIN users u ON l.user_code = u.user_code
WHERE l.action = 'login'
  AND l.log_time >= '2024-06-01'
ORDER BY l.log_time DESC
LIMIT 50;
```

原始查询14s

给关联字段加索引`ALTER TABLE users ADD INDEX idx_user_code (user_code);`

只需0.084s
